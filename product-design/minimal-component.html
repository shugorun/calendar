改修案（2026-06 のUI課題）

実利用で出た課題のうち UI に回す5件。意図・web/ 移植・バックエンドの申し送りは redesign-notes.md 参照。抽出まわり（日付なし/不正→未定、取り込み後の即時表示）は対応済み。

① 画像サムネの開閉を滑らかに（.intake-media）

.intake（サムネ無し＝閉）

.intake（サムネ有り＝開）

.intake-media を常設し :has(.intake-thumb) で grid-template-rows: 0fr → 1fr ＋ opacity を 0.25s。高さが伸びて下も滑らかに動く。prefers-reduced-motion で無効化。

⑤ 手動追加: 入力バー左のカレンダーicon → イベント作成フォーム（イベント名＋予定を複数）

.intake + .intake-cal（左のカレンダーicon）／ .manual-add（白枠・イベント名＋予定複数・下センターで追加）

入力バー左のカレンダーicon（.intake-cal）で .manual-add をトグル。中身はイベント詳細画面とほぼ同じ＝最上部に .title-form のイベント名、その下に .sched カードを複数（.sched-add で増やす＝⑧と共通）。確定は .sched-commit 行の「確定」チェック1つ（オンで .sched.committed 表示。浮いているが既定）。白背景は無し、幅も入力バーに合わせない（詳細画面と同じ）。追加ボタンは下センター。日付を空にした予定は日時未定。要 POST /api/manual（event_title＋schedules[]）。

不正/読めない日付（例 6/31）は未定に落とした上で要確認表示。正当な未定（7月中・後日発表）はニュートラルのまま。

⑧ 詳細画面に予定を追加（グルーピング .sched-add）

イベント詳細: .sched-list の下に .sched-add（同じイベントに予定を足す）

  • 浮いている

既存イベント（普通のチップから開いた詳細画面）でも .sched-add で同じイベントに予定を足せる。押すと空の予定を1件作成→その場でインライン編集（自動保存）。要 POST /api/events/{id}/schedules。

product-design / minimal-component — クラス名は web/ に 1:1。申し送り（web/ へ着せる時の小変更）: 取り込みフォームをチャット入力風コンポーザーに再構成（新設 intake-row · intake-add（＋ボタン＝ファイル選択） · intake-submit · intake-thumbs · intake-thumb · intake-thumb-x）。自動保存化により予定・タイトル・ノートの保存ボタンは廃止、削除は確定トグルと同じ行へ。「時刻」→「開始時刻」、一括確定は「予定をまとめて確定／予定の確定を取り消す」。その他の新設クラス button.primary · chip.deadline · chip.approximate · cal-more · sched-state.is-committed · sched-flags · event-title。溢れは .cal-more ボタン＋ネイティブ Popover API （.day-popover、JS不要）で日別ポップオーバー表示（React 19 の popover/popoverTarget で移植可・配置は anchor positioning）。
