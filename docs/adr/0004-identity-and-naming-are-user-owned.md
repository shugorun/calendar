# 識別と命名はユーザー所有（AIに任せない）

再取り込みによる更新で「同じイベント／予定か」の判定を、AIの自動マッチに任せない。各イベント・予定は内部の固定IDで識別し、再取り込み時はユーザーが「新規作成」か「既存のどれを更新／追加するか」を選ぶ。AIが付けた名前は表記が揺れるため正しさの根拠にせず、ユーザーが編集した名前は固定（以後AIが上書きしない）。

AI生成の名前・ラベルは表記揺れが避けられず（「応募締切」「締切」「〆切」…）、自動マッチに依存すると誤マッチと重複が原理的に起きるから。

## Consequences

- 更新フローにユーザー操作が1つ入る（ゼロ手間ではない）。これは誤マッチ・重複を防ぐための意図的なコスト。
- 種類などの表示ラベルはAIの自由テキストのまま持ってよい（識別には使わないので揺れが害にならない）。
